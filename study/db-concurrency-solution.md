# 정리 배경
- 재고 차감시 여러 스레드가 동시에 접근할 경우, 동시성 이슈로 재고 수량의 정합성이 깨지는 이슈가 생길 수 있다.
예. 재고가 1개 남았을때 두명의 사용자가 각각 하나씩 주문하면 한명만 주문에 성공해야 하는데, 
두 요청이 동시에 발생시 두명 다 주문에 성공해버리는 경우가 생김.

## 비관락
- 개념
    - DB에 변경이 자주 발생하고, 충돌 가능성이 높은 환경에서 선호.
        - 충돌이 발생할것이라고 비관적으로 가정하고 데이터를 처음부터 잠근다.
- 예시
    - 동시 주문 요청이 아주 많지만, 재고가 마이너스 되는 현상을 절대 허용할 수 없을때.
- 장점
    - 데이터 베이스 수준에서 순차처리 보장하므로 정합성이 완벽하다
- 단점
    - 먼저 온 요청이 끝날때까지 뒤의 요청이 DB 커넥션을 잡고 대기하므로, 트래픽이 몰리면 고객이 긴 로딩을 겪는다.
## 낙관락
- 개념
    - DB에 변경이 드물게 발생하고, 충돌 가능성이 낮은 환경 선호.
        - 충돌이 드물게 발생한다고 '낙관적'으로 가정. 실제로 충돌이 발생할때만 대응
