# ADR-0006: 주문 API — 응답 모델 & 멱등키 저장

- **상태**: Accepted (2026-06-27)

---

## 1. 요구사항
- 주문 생성 응답 스펙 확정 필요 
- 주문 중복 생성 방지용 로직 추가 필요

---

## 2.결정 
### 2.1 인바운드 응답 모델
- `202 Accepted` +`{orderId}` 즉시 반환
- 클라이언트는 **폴링**으로 최종 주문 상태 확인 (`GET /orders/{id}` )

---

### 2.2 멱등키 저장 메커니즘
- 1차 방어: Redis로 1차로 idempotency_key 저장. 사용자 요청 동시에 왔을때 한쪽만 튕겨낸다.
- 2차 방어: `orders` 테이블에 `idempotency_key` UNIQUE 컬럼
